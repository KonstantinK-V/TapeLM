# Pre-publish frontier — тех-план (2026-07-29)

**Рамка публикации (принята):** ценность работы — **не** «догнали RAG / кое-где лучше», а **«делаем иначе,
получаем сопоставимое, и вот карта того, что снято и что открыто»**. Публикация = приглашение: вот лента и
fp-пространство, вот опровергнутые ветки (B, free-form internal reader, hybrid), вот три места, где субстрат
может вести себя не как BPE+индекс. Публикация не торопится — сначала докопать фронтир.

**Словарь вердиктов (новый, не «WIN vs RAG»):**

| вердикт | смысл |
|---------|-------|
| `THESIS_YES` | получено свойство, которое **нельзя** переписать как «ещё один RAG-ключ» без смены субстрата |
| `ENGINEERING_ONLY` | работает, но эквивалентно внешнему zero-train циклу → ценность имплементационная |
| `THESIS_NO` | свойство не получено → идёт в карту негативов, не в hook |

**Нумерация.** Порядок исполнения = порядок номеров (чтобы логи/JSON читались линейно):

| новый № | рабочее имя из обсуждения | тема |
|---------|---------------------------|------|
| **210** | «212-lite» | structured composition **внутри** forward, ответ **токенами** |
| **211** | «210» | beyond-window / cross-doc **внутренняя** медленная лента vs endpoint |
| **212** | «211» | instance / content-invariant канал (collision, para vs hard) |

**Общие инварианты для всех трёх (жёстко):**

- P1 `checkpoints/stage191_p1_curve.pt` (`SelfModelXL`, d=256, 6L) **заморожен**; anti-CF assert по сумме
  |params| для `arc_enc`, `fast`, `slow`, `head` до и после (как в 203).
- Обучаются только новые мелкие модули; любой инъекционный путь — **zero-init gate**, чтобы «выключенный»
  режим был **бит-идентичен** P1 (проверяется отдельным ассертом, а не «на глаз»).
- Anti-Goodhart (188): сигналы интроспекции, влияющие на выход, **detach** от CE-градиента.
- Уроки, которые нельзя нарушать: **185** — рукотворные вспомогательные лоссы травят CE; **203** — свободный
  обучаемый ридер запоминает цепочки; **207** — выход как «следующий отпечаток» = предсказание написания.
- Каждый стейдж пишет `results/stage2XX_decision.json`, `stage2XX_mini.md`, `_stage2XX_log.txt`.
- Бюджет 3050: один стейдж ≤ ~60 мин GPU; `MAX_ARCS=64`, batch подбирается под 4 ГБ.

## Stage 210 — structured composition в forward, ответ токенами

### Зачем (чего не было в 203)

203 доказал: внутренние хопы генерализуются **только** при минимальной структуре (soft retrieve → follow →
выбор глубины), а свободный ридер — заучивает. Но 203 **читал ответ косинусом в fp-пространстве**, т.е. хопы
всё ещё были «вне языка». Нерешённый вопрос: можно ли сделать композицию **частью того же forward, что
генерирует текст**, и получить ответ **через CE-head токенами** — без CoT, без генерации fp (урок 207), без
разморозки P1.

Это и есть форма, которая может «натолкнуть на большее»: фиксированная **программа над лентой** внутри блока,
а не внешний скрипт и не свободный MLP.

### Что реализуем

`SoftFollowBlock` — обёртка над `SoftFollow` из 203 + инъекция результата в поток арок:

```
retrieved = SoftFollow(fp(A0), k, K, V)        # параметр-free, учится только температура
mem_arc   = gate * W_inject(retrieved)         # W_inject zero-init → gate=0 ⇒ P1 бит-идентичен
arcs'     = [arcs_ctx ; mem_arc]               # одна «memory-arc» перед слотом ответа
logits    = P1.head([fast(arcs'), slow(arcs')])
```

- Ответ читается **как токены**: `span_logprob_x` (из 191) по 4 кандидатам, а не косинус к `fp(cand)`.
- Обучается: `W_inject`, `gate`, `log_temp`. P1 — frozen. Лента слотов `K/V` — **non-gradient**.
- Данные: протокол 203 (planted fake-цепочки `gen_fakes`, `CHAIN_LEN=4`, сплит **по цепочкам**), но вопрос
  оформлен текстом-запросом, чтобы ответ шёл через голову.

### Условия сравнения

| ветка | роль |
|-------|------|
| `soft_follow_token` (наша) | structured блок, ответ токенами |
| `free_form_token` | тот же путь, но `HopReader` из 203 — **должен снова переобучиться** (контроль формы) |
| `external_loop` + cosine | reference из 203/200 (ожидаем ~1.00) |
| `no_memory` (gate=0) | контроль: без инъекции задача нерешаема (≈ chance) |
| matched GPT (P2), контекст усечён | слабый baseline: факт вне окна |

### Гейты

| id | критерий |
|----|----------|
| G1 generalize | `soft_follow_token` test (unseen chains) k2 ≥ 0.70, k3 ≥ 0.60 (chance 0.25) |
| G2 structure matters | `free_form_token`: train ≥ 0.90 **и** test ≤ 0.45 (форма важна, не мощность) |
| G3 no-CE-cost | next-token на обычном тексте при **включённом** блоке: Δ ≤ 0.01 против P1 |
| G4 bit-identity | при `gate=0` логиты бит-идентичны P1 (assert), anti-CF суммы неизменны |
| G5 needs memory | `no_memory` ≤ 0.35 |

### Вердикт

- `THESIS_YES` — G1–G5 пройдены: композиция живёт **внутри** одного forward, отвечает **языком**, не стоит CE,
  и не требует градиента на бэкбон. Формулировка для статьи: *«hop-composition как fixed latent program на
  ленте, а не как decode-цепочка»*.
- `ENGINEERING_ONLY` — G1 прошёл, но точность ≤ external loop и никакого нового свойства (только один граф).
- `THESIS_NO` — G1 провален (structured блок в token-space не генерализует) → значит внешний zero-train цикл
  остаётся единственной честной формой; пишем как негатив.

### Риски / стоп-условия

- Инъекция одной арки может «утонуть» в 64-арочном окне → пробуем позицию **непосредственно перед** слотом
  ответа и, при провале, `n_mem_arcs=2` (не больше — иначе это уже prompt-stuffing).
- Если для G1 понадобится разморозить хоть один параметр P1 — **стоп**, это ломает anti-CF контракт.

**Оценка работы:** ~250–300 строк, 1 прогон ~25–40 мин.

**Result (2026-07-29):** `THESIS_NO` — external cosine hops 1.0; token inject path ~chance (test k2=0.25 k3=0.30);
next_tok delta 0; see `results/stage210_decision.json`.

## Stage 211 — beyond-window: внутренняя медленная лента vs endpoint

### Зачем

В плане с 183 зафиксировано: **лента хранит «что стало известно», а не траекторию пера**, и `z_T` не должен
быть памятью (нужны адресуемые слоты + query). 185 показал, что чтение ленты **внутри окна** декоративно —
мотивирующий кейс именно **за окном** и **между документами**. Сейчас все победы памяти (194–198) — на
**внешних** слотах. Вопрос: даёт ли **внутренняя** медленная лента что-то, чего не даёт endpoint, при
**одном** проходе и без повторного чтения источника.

### Что реализуем

- Из `SurpriseWriter` (187) в P1 уже есть surprise-gated медленный канал. Добавляем **инференс-only логгер**:
  на шагах с высоким surprise сохраняем `(key = ctx_fp окна, value = slow_t)` в **non-gradient** буфер —
  «внутренняя лента», побочный продукт того же прохода, без отдельного энкодера.
- Читаем структурированным `SoftFollow`-подобным запросом (t=1, т.е. retrieve, без follow) → инъекция как в
  210 (тот же `SoftFollowBlock`, режим `t=1`).
- Данные: cross-doc — факт в документе A, вопрос в документе B; между ними ≫ `MAX_ARCS=64` арок
  (переиспользуем `build_stream` из 198 + boilerplate-давление).

### Условия сравнения

| ветка | роль |
|-------|------|
| `internal_tape` (наша) | слоты из медленного канала, чтение внутри forward |
| `endpoint_only` | тот же P1, память = `slow_T` (то, что мы считаем неправильной формой) |
| `external_slots` | TapeLM 194/198 — **reference**, верхняя граница |
| `gpt_incontext` | matched GPT, окно усечено — структурно не может |
| `doc_id_oracle` | **честный контроль**: слот-ключ = id документа, без fp-геометрии |

`doc_id_oracle` тут важен: если он равен `internal_tape`, значит мы измеряем метаданные, а не субстрат.

### Гейты

| id | критерий |
|----|----------|
| G1 beats endpoint | `internal_tape` − `endpoint_only` ≥ 0.25 |
| G2 near external | `internal_tape` ≥ `external_slots` − 0.10 |
| G3 beyond window | `gpt_incontext` ≤ 0.35 (задача действительно вне окна) |
| G4 not metadata | `internal_tape` ≥ `doc_id_oracle` − 0.05 при **шумном** варианте (30% char-noise): fp-ключ должен держаться там, где id недоступен/сломан |
| G5 anti-CF | P1 не тронут; буфер non-gradient |

### Вердикт

- `THESIS_YES` — G1+G2+G3+G5 и G4 (не сводится к doc-id): *«медленный канал — адресуемое состояние знания,
  возникающее как побочный продукт одного прохода»*.
- `ENGINEERING_ONLY` — G1+G2, но G4 провален → это внутренний индекс, эквивалент RAG-ключа.
- `THESIS_NO` — G1 провален: endpoint не хуже → адресуемость ленты не подтверждена (важный негатив против
  собственного концепта из 183).

**Оценка работы:** ~300–350 строк, 1 прогон ~30–50 мин (нужны прогоны по потоку, не тренировка).

**Result (2026-07-29):** `THESIS_NO` — internal 0.23 < endpoint 0.28; external 1.00; gpt_ic 0.26; see `stage211_decision.json`.

## Stage 212 — instance / content-invariant канал

### Зачем (самый «никто так не собирал», и самый рискованный)

Два незакрытых узла, которые встречаются здесь:

1. **Коллизии** одинаковых поверхностей (старый пункт: dense H1 / hop2-joint упирались в коллизии; soft-disambig
   не спас — нужен другой **канал**, а не более мягкий rerank).
2. **Медленный канал как content invariant** (пункт 3 из «LOCKED direction», 178/180/190): одинаков при
   перефразе, различен при minimal-pair различии написания. 199–201 показали: голова на frozen не помогает,
   а fine-tune энкодера ломает CE (202b). Значит нужен **отдельный узкий канал**, не переписывание P1.

### Что реализуем

Второй канал **identity/instance** над той же лентой (не метаданные, а функция локального контекста):

```
inst_t = normalize( g( ctx_fp(local window around occurrence), position_signature ) )
```

- `g` — маленький модуль (2 слоя), обучается **контрастно**: одно и то же вхождение → близко; **другое
  вхождение того же слова** → далеко; перефраза того же содержания → близко.
- CE не трогаем совсем (P1 frozen; урок 185 — никаких вспомогательных лоссов в CE-путь).
- Ключ слота становится парой `(fp(word), inst)`; поиск — по сумме косинусов с обучаемым весом (1 скаляр).

### Тесты

| тест | что проверяет |
|------|---------------|
| T1 collision | 2 сущности с **одинаковой** поверхностью, разные факты; запрос различает только по контексту-cue |
| T2 para/hard | пары из 190/179: `cos(inst)` — para **выше** hard (инверсия, которой никогда не было) |
| T3 no-CE-cost | next-token P1 неизменен (канал read-only, вне CE) |
| T4 ablation: doc-id | заменяем `inst` на doc-id/позицию → если результат тот же, это метаданные |
| T5 ablation: soft-rerank | вместо канала — мягкий rerank (то, что уже провалилось) → должен быть хуже |

### Гейты

| id | критерий |
|----|----------|
| G1 collision | T1 accuracy ≥ 0.70 при `fp`-only baseline ≤ 0.45 (chance 0.25) |
| G2 invariant | T2: `para > hard` на **held-out** парах (первая инверсия в программе) — или хотя бы gap < 0 |
| G3 not metadata | G1 сохраняется при doc-id ablation **хуже** на ≥ 0.10 |
| G4 not old trick | превосходит soft-rerank (T5) на ≥ 0.10 |
| G5 no CE cost | Δ next-token ≤ 0.005; anti-CF assert |

### Вердикт

- `THESIS_YES` — G1+G3+G4+G5 (G2 бонусом): *«канал идентичности вхождения на той же ленте решает коллизии,
  которые RAG-ключ на поверхности слова решить не может»*. Если ещё и G2 → это первый реальный сдвиг по смыслу
  в программе.
- `ENGINEERING_ONLY` — G1 есть, но G3/G4 провалены → это переупакованный doc-id или старый rerank.
- `THESIS_NO` — G1 провален → канал идентичности не даёт разрешения коллизий; закрываем ветку письменно и
  публикуем как негатив (что честно закрывает и старый hop2/joint долг).

**Оценка работы:** ~350–400 строк, 1–2 прогона по ~40–60 мин (контрастное обучение мелкого модуля).

**Result (2026-07-29):** `THESIS_NO` — collision 4-way: instance 0.378 vs untrained 0.336 vs ctx_blend 0.328 vs
fp_only 0.242; para 0.750 < hard 0.937 (no inversion); next_tok Δ 0. See `stage212_decision.json`.

## ФРОНТИР ЗАКРЫТ (2026-07-29)

Все три ставки не прошли, и **каждая по своей причине** — это и есть результат:

| стейдж | что пробовали | почему не вышло |
|--------|----------------|------------------|
| 210 | hop внутри forward, ответ токенами | retrieve→BPE-span одной memory-arc не выучивается без градиента на P1; внешний zero-train цикл остаётся 1.0 |
| 211 | адресуемая медленная лента cross-doc | слоты по surprise хуже endpoint (0.23 vs 0.28), явные fp-слоты 1.0 — «endpoint ≠ memory» не подтверждено |
| 212 | канал идентичности вхождения | обучение даёт +0.04 к необученной проекции того же состояния; para 0.75 < hard 0.94 — состояние кодирует форму, не содержание |

**Цена — нулевая:** во всех трёх P1 остался заморожен, генерация не изменилась (Δ next_tok = 0, bit-identity 0).

**Что это значит для публикации.** Hook остаётся тем, что уже измерено в 191–209: **variant A** как единое
fp-пространство (генерация + память + калибровка + правка на одном замороженном энкодере) **плюс плотная карта
негативов** — B опровергнут (207/207-MAX), гибрид не нужен (208), смысл структурно не заблокирован, но и не
подтверждён на 3050 (209), а «лента умеет больше, чем внешний индекс» не подтверждается **тремя независимыми
способами** (210–212). Для рамки «делаем иначе, получаем сопоставимое» это честный и полный набор: **что
работает, что нет и почему**.

**Открытым остаётся только hardware-трек:** смысловой objective на энкодере большего масштаба (209 показал
траекторию как у GPT). Всё остальное в этом репозитории закрыто письменно.
